================================================================================
GLOBAL RULES — READ BEFORE EXTRACTING
================================================================================

RULE 1: MISSING VALUES
If a field is not mentioned in the document, use the string "N/A".
Never use null, None, empty string "", or NaN.

RULE 2: NUMERIC FIELDS
These fields must contain ONLY a whole number or "N/A" — no text, no units, no currency
symbols, and NO decimal point (write 18, not 18.0):
MIN_AGE, MAX_AGE, MIN_BALANCE, AVG_BALANCE_REQUIREMENT, MIN_INCOME, MIN_INCOME_USD,
MIN_INVESTMENT, MIN_CONTRIBUTION, MIN_TERM_YEARS, MAX_TERM_YEARS, FREE_LOOK_PERIOD_DAYS,
IS_BANK_OFFERED
Before writing a numeric field, strip any trailing ".0" and any thousands separators or
currency symbols.

RULE 3: SOURCE FILE
SOURCE_FILE_PRODUCT = only the filename of the document you were actually given
(e.g. "ProductName.docx"), never the full folder path.
If one input document/file describes several products, use that SAME filename for every
product extracted from it. NEVER invent, guess, or construct a filename from the product
name — only report the filename the source content actually came from.

RULE 4: ONE PRODUCT PER JSON, EXTRACT EVERY PRODUCT
Each JSON object describes exactly one product. If the document contains multiple products,
first list every distinct product heading/section in the document, then produce one JSON
object for each one — do not stop early and do not skip a product because it appears near
the end of the document. Return a JSON array of these objects when more than one product is
found. The number of JSON objects returned MUST equal the number of distinct products in the
document.

RULE 5: IS_BANK_OFFERED
Use 1 if the product is distributed through a bank OR requires being a bank customer.
Use "N/A" only if it is completely independent of any bank.

RULE 6: NO CROSS-PRODUCT CONTAMINATION
When a document describes multiple products, extract every field ONLY from that specific
product's own section (its own heading, table, or paragraph block). Never reuse, copy, or
"borrow" a value (coverage amounts, exclusions, fees, free-look period, tiers, etc.) from a
different product in the same document just because it looks similar. If THIS product's own
section does not mention a field, output "N/A" for it — do not fill it in from elsewhere in
the document.

RULE 7: DO NOT TRUNCATE MID-WORD
For any field with a max character length, cut at the nearest word or punctuation boundary
(comma, semicolon, space) so the value never ends on a broken word or number. Prefer
shortening by dropping a trailing clause over cutting a word in half.

COLUMN-BY-COLUMN RULES
================================================================================

1. PRODUCT_NAME (max 50 chars)
   Extract the exact product name from the document heading. Trim extra spaces.
   Example: "Alfalah Insurance Zaamin Takaful Plan"

2. LEAD_MARKER
   EXACTLY one of: "IBG" or "BNK"
   - IBG = Insurance, Takaful, Protection, Endowment, Health plan
   - BNK = Bank account, card, loan, deposit

3. SOURCE_FILE_PRODUCT
   ONLY the filename, not the full path.
   WRONG: "/content/Data/Banca Takaful/ProductName.docx"
   CORRECT: "ProductName.docx"

4. PLAN_TYPE
   EXACTLY one word from: Insurance | Savings | Deposit | Loan | Card | Investment | Service | Loyalty
   Insurance/Takaful/Endowment/Protection plans → "Insurance"
   Do NOT use "Savings" for a Takaful savings plan — use "Insurance"

5. TARGET_GOAL
   EXACTLY one value (max 30 chars):
   Protection | Education | Health | Savings | Marriage | Housing | Investment | Retirement | Wellness | General

   DECISION TREE — check product NAME first:
   - Name contains "Education" or "Danish" → Education
   - Name contains "Marriage" or "Uroos" → Marriage
   - Name contains "Shifa" or "Health" → Health
   - Name contains "Zeenat" → Savings
   - Name contains "Zaamin" → Protection
   - Name has no keyword → check description/purpose

6. CUSTOMER_TYPE
   EXACTLY one value from: Salaried | Self-Employed | SME | Corporate | Retail | Government | N/A
   If the product is open to all bank customers → "Retail"
   NEVER use comma-separated lists.

7. EMPLOYMENT_TYPE
   EXACTLY one value from: Salaried | Self-Employed | Government | Military | N/A
   
   HOW TO EXTRACT:
   - Look for a "Target Market" section in the document FIRST
   - If "Target Market" lists Salaried Individuals first → "Salaried"
   - If Target Market section does NOT exist for this product (e.g. Zaamin, Shifa) → "N/A"
   - "Self Employed Individuals, Proprietors" → Self-Employed
   - "Government / Armed Forces" → Government
   
   IMPORTANT: Do NOT assume Salaried if there is no Target Market section.

8. CUSTOMER_SEGMENT (max 50 chars)
   WHO the product is for, stated as a short audience label — NOT a full eligibility
   sentence and NOT a list of employment types.
   Correct style: "All Bank Customers", "Female Customers and Spouse", "SME Business Owners"
   WRONG: pasting the full eligibility/Target Market paragraph verbatim.
   If a general "open to all customers" statement exists, summarize it as
   "All Bank Customers" (or "All [Bank Name] Customers") rather than listing every
   employment category named in the document.
   If not mentioned → "N/A"

9. TARGET_SEGMENT (max 50 chars)
   WHAT need/goal the product addresses, stated as a short 2-4 word planning label —
   NOT a repeat of CUSTOMER_SEGMENT and NOT an eligibility description.
   Correct style: "Education Planning", "Healthcare Coverage", "Marriage Planning",
   "Protection Planning", "Savings Planning"
   Derive from TARGET_GOAL if not explicitly stated (e.g. TARGET_GOAL "Health" →
   "Healthcare Coverage").
   If not mentioned → "N/A"

10. SEGMENT_TIER
    EXACTLY one value from: Mass Market | Retail | Premium | Niche
    
    DECISION TREE (apply in this exact order):
    Step 1: If GENDER = "Female" → "Niche"
    Step 2: If MIN_CONTRIBUTION >= 250000 → "Premium"
    Step 3: If TARGET_GOAL = "Health" AND open to all customers → "Mass Market"
    Step 4: Otherwise → "Retail"

11. MIN_AGE
    Number only. Example: 18
    Extract from eligibility section.

12. MAX_AGE
    Number only. Extract the ENTRY age limit (not the maximum attained age).
    Example: eligibility says "18 to 55 years" → MAX_AGE = 55
    Do NOT use 85 if 85 is the maximum "attained" age, not the entry age.

13. GENDER
    EXACTLY one of: "All" | "Male" | "Female" | "N/A"
    - Product explicitly restricted to females only → "Female"
    - Product explicitly restricted to males only → "Male"
    - Eligibility/target market section exists and does NOT restrict by gender → "All"
      (this is the default whenever an eligibility section is present but silent on gender —
      do NOT output "N/A" just because gender isn't explicitly mentioned)
    - Use "N/A" ONLY when there is no eligibility/target market information at all
    CASE MATTERS: use exact capitalization shown above.

14. IS_BANK_OFFERED
    1 = product is offered through a bank or requires bank customer status
    "N/A" = completely independent product
    All Banca Takaful products distributed via Bank Alfalah → use 1

15. ACCOUNT_TYPE
    EXACTLY one of: Current | Savings | Wallet | Digital | N/A

    IMPORTANT: Do NOT use "Savings" for a savings-oriented INSURANCE plan.

16. CARD_TYPE
    EXACTLY one of: Debit | Credit | Virtual Debit | Premium | N/A

    Otherwise → "N/A"

17. CHANNEL (max 30 chars)
    How customers can access the product.
    Examples: "Bank Branch", "Mobile App", "Online", "Call Center", "Direct"
    All products available via Bank Alfalah branches → "Bank Branch"
    If not mentioned → "N/A"

18. ELIGIBILITY_TYPE (max 50 chars)

================================================================================
STEP-BY-STEP EXTRACTION WORKFLOW
================================================================================

STEP 1: Identify the product
  → Is it insurance/takaful/protection? → LEAD_MARKER = "IBG", PLAN_TYPE = "Insurance"
  → Is it a bank account/card/loan? → LEAD_MARKER = "BNK"

STEP 2: Extract product name, provider, source file
  → PRODUCT_NAME from heading
  → PROVIDER_NAME from document text (who underwrites it)
  → SOURCE_FILE_PRODUCT = filename only, no path

STEP 3: Determine TARGET_GOAL
  → Check product NAME first (keywords: Education, Marriage/Uroos, Shifa/Health, Zaamin/Protection)
  → If no keyword in name, read the description

STEP 4: Set SERVICE_TYPE from TARGET_GOAL using the mapping in Rule 19

STEP 5: Extract eligibility (ages, gender, customer type)
  → MIN_AGE, MAX_AGE from eligibility section
  → MAX_AGE = entry age limit, NOT maximum attained age
  → GENDER = "Female" only if explicitly female-only product
  → Check for "Target Market" section → set EMPLOYMENT_TYPE

STEP 6: Set SEGMENT_TIER using the 4-step decision tree in Rule 10

STEP 7: Extract financial parameters
  → MIN_CONTRIBUTION = minimum annual contribution (number only)
  → DEPOSIT_PROFIT_TYPE: check for unit-linked, bonus allocation
  → DEPOSIT_PROFIT_FREQUENCY: default "At Maturity" for savings; "N/A" for health/protection

STEP 8: Extract SPECIAL_CONDITIONS (max 200 chars)
  → Free look period, policy limits, important restrictions only

STEP 9: Extract benefits, riders, documents, claims contact, exclusions

STEP 10: VALIDATE before output:
  ☑ One JSON object exists for EVERY distinct product found in the document (recount them)
  ☑ All 55 fields present in each object
  ☑ No null/None/NaN values — use "N/A"
  ☑ GENDER is exactly "All", "Male", "Female", or "N/A" (exact case); default "All" when
    eligibility exists but doesn't restrict gender
  ☑ CURRENCY_TYPE is exactly "PKR", "FCY", "PKR + FCY", or "N/A"
  ☑ CUSTOMER_TYPE has exactly ONE value (no commas)
  ☑ PLAN_TYPE is one word
  ☑ Numeric fields contain ONLY whole numbers (no ".0") or "N/A"
  ☑ SPECIAL_CONDITIONS is under 200 characters, cut at a word boundary
  ☑ SOURCE_FILE_PRODUCT has no folder path, and is identical across all products from the
    same source document
  ☑ DEPOSIT_PROFIT_TYPE / DEPOSIT_PROFIT_FREQUENCY = "N/A" only for pure health/protection
    products with no savings/investment component
  ☑ ACCOUNT_TYPE = "N/A" for insurance plans
  ☑ No value in any field was copied from a different product's section
  ☑ No markdown — output ONLY the JSON object(s)

================================================================================
GENERAL PATTERN REFERENCE (applies to any bank/insurer/product)
================================================================================

Use these general patterns instead of memorizing specific products:

- PRODUCT_NAME: normalize casing/spacing from the heading; do not output an ALL-CAPS
  heading verbatim if the rest of the document uses normal title case.
- CUSTOMER_TYPE: if the product is open to all bank customers regardless of employment
  type, use "Retail" even if a Target Market list happens to mention "Salaried" first.
- Products with no dedicated "Target Market" section but sold through a bank branch are
  still bank-offered (IS_BANK_OFFERED = 1); the absence of a Target Market section affects
  EMPLOYMENT_TYPE, not IS_BANK_OFFERED.
- MAX_AGE: use the ENTRY age limit from eligibility, not a "renewable to" or "maximum
  attained age" figure — UNLESS the product has no separate entry-age cutoff, in which case
  use the one age limit that is given.
- A product name containing a purpose word (Education, Marriage, Health, Protection,
  Savings, Retirement, etc., in any language used by the source bank) should drive
  TARGET_GOAL and SERVICE_TYPE consistently with the mapping in Rule 19.
- SEGMENT_TIER, DEPOSIT_PROFIT_TYPE/FREQUENCY, ACCOUNT_TYPE, CARD_TYPE, TENURE_OPTIONS:
  apply the decision rules in their own numbered sections above to each product's own
  content — never copy a sibling product's resolved value.

================================================================================
COMMON MISTAKES TO AVOID FOR SMALL MODELS
================================================================================

MISTAKE 1: Using full file path in SOURCE_FILE_PRODUCT
  WRONG: "/content/Data_Extraction/Documents/Banca Takaful/ProductName.docx"
  CORRECT: "ProductName.docx"

MISTAKE 2: Setting DEPOSIT_PROFIT_TYPE = "Variable" for health/protection insurance
  CORRECT: Set "N/A" for Shifa and Zaamin plans

MISTAKE 3: Setting DEPOSIT_PROFIT_FREQUENCY = "At Maturity" for health/protection
  CORRECT: Set "N/A" for Shifa and Zaamin plans

MISTAKE 4: Confusing payment frequency with profit frequency
  "Payment Frequency: Annual/Quarterly" = how customer pays → NOT DEPOSIT_PROFIT_FREQUENCY
  DEPOSIT_PROFIT_FREQUENCY for savings plans = "At Maturity" (default)

MISTAKE 5: Using MAX_AGE = 85 when 85 is "max attained age"
  Read the eligibility: "18 to 65 years of age" → MAX_AGE = 65

MISTAKE 6: Using ACCOUNT_TYPE = "Savings" for savings-oriented insurance plans
  Insurance/Takaful plans → ACCOUNT_TYPE = "N/A"

MISTAKE 7: Setting IS_BANK_OFFERED = 0 for Banca products
  All products sold via Bank Alfalah branches → IS_BANK_OFFERED = 1

MISTAKE 8: Setting GENDER = "All" for Zeenat (female-only product)
  Always check if the product is gender-specific: Zeenat → GENDER = "Female"

MISTAKE 9: Copying FREE_LOOK_PERIOD_DAYS from one product to another
  Only set 14 if THIS product's section explicitly mentions a 14-day free look period.
  Zaamin does NOT mention a free look period → FREE_LOOK_PERIOD_DAYS = "N/A"

MISTAKE 10: TENURE_OPTIONS = "1M -> 5Y" (invented format)
  Use what the document actually says about contribution frequency or term options.
  IGI savings plans → "Annual, Semi-Annual, Quarterly contributions"

MISTAKE 11: Using "nan" or null in JSON
  Replace all with "N/A"

MISTAKE 12: CUSTOMER_TYPE = "Salaried Individuals" 
  Must be exactly one of: Salaried | Self-Employed | SME | Corporate | Retail | Government | N/A

MISTAKE 13: PLAN_TYPE = "Savings" for a Takaful savings plan
  Takaful savings plans are still Insurance → PLAN_TYPE = "Insurance"

MISTAKE 14: TARGET_GOAL = "N/A" when the product name or description clearly implies a
  purpose (education, marriage, health, protection, savings, retirement, etc.)
  Always resolve TARGET_GOAL to a concrete value if any purpose keyword exists.

MISTAKE 15: SPECIAL_CONDITIONS containing fee schedules or full feature lists
  Keep it under 200 chars with only critical conditions (look period, waiting periods, key restrictions)

MISTAKE 16: Copying a field value (coverage tiers, exclusions, fees, riders) from one
  product into a different product in the same document because they look similar
  Extract every field strictly from that product's own section; use "N/A" if that
  product's own section doesn't mention it.

MISTAKE 17: Writing numeric fields with a trailing decimal, e.g. "18.0" or "250000.0"
  Always output whole numbers as plain integers: "18", "250000"

MISTAKE 18: Stopping partway through a multi-product document and leaving remaining
  products (especially ones near the end) mostly "N/A" or omitting them entirely
  Count all product sections first, then produce a complete object for each one.
