================================================================================
GLOBAL RULES — READ BEFORE EXTRACTING
================================================================================

RULE 1: MISSING VALUES
If a field is not mentioned in the document, use the string "N/A".
Never use null, None, empty string "", or NaN.

RULE 2: NUMERIC FIELDS
Must contain ONLY a whole number (no units, no currency, no decimal point) or "N/A":
MIN_AGE, MAX_AGE, MIN_BALANCE, AVG_BALANCE_REQUIREMENT, MIN_INCOME, MIN_INCOME_USD,
MIN_INVESTMENT, MIN_CONTRIBUTION, MIN_TERM_YEARS, MAX_TERM_YEARS,
FREE_LOOK_PERIOD_DAYS, IS_BANK_OFFERED
Strip trailing ".0" and any thousands separators or currency symbols.
Write 18 not 18.0. Write 250000 not PKR 250,000.

RULE 3: SOURCE FILE
SOURCE_FILE_PRODUCT = only the filename (e.g. "ProductName.docx"), never the full path.
Never invent, guess, or construct a filename from the product name.

RULE 4: ONE PRODUCT PER JSON
Each JSON object describes exactly one product. Multiple products → JSON array.
Count all product sections first, then produce a complete object for each one.

RULE 5: IS_BANK_OFFERED
1 = product distributed through a bank or requires bank customer status.
"N/A" = completely independent of any bank.

RULE 6: NO CROSS-PRODUCT CONTAMINATION
Extract every field ONLY from that specific product's own section.
Never copy values from a different product in the same document.
If THIS product's section does not mention a field → "N/A".

RULE 7: EXTRACT ONLY — DO NOT DERIVE
For these fields: CUSTOMER_SEGMENT, TARGET_SEGMENT, SEGMENT_TIER, SERVICE_TYPE,
CHANNEL, ELIGIBILITY_TYPE, GENDER, CURRENCY_TYPE — output "N/A" unless the
value is EXPLICITLY stated in the document. Do NOT derive or infer from other fields.

RULE 8: TITLE CASE
Normalize PRODUCT_NAME to Title Case. Never output ALL-CAPS headings verbatim.
WRONG: "JUBILEE KAMIL TAKAFUL SAVINGS PLAN"
CORRECT: "Jubilee Kamil Takaful Savings Plan"

================================================================================
COLUMN-BY-COLUMN RULES
================================================================================

1. PRODUCT_NAME (max 50 chars)
   Extract from heading. Normalize to Title Case.

2. LEAD_MARKER
   EXACTLY "IBG" or "BNK".
   IBG = Insurance, Takaful, Protection, Endowment, Health plan
   BNK = Bank account, card, loan, deposit

3. SOURCE_FILE_PRODUCT — filename only, never a full path (see Rule 3).

4. PLAN_TYPE
   EXACTLY one value from: Insurance | Protection | Health | Savings | Deposit |
   Loan | Card | Investment | Service | Loyalty
   - Pure accident/theft protection (no investment component) → "Protection"
   - Hospitalization/medical plans → "Health"
   - Savings/endowment plans with investment fund allocation (PIA, unit-linked) → "Savings"
   - Investment-focused plans (surplus sharing, investment-primary) → "Investment"
   - Traditional life insurance/takaful with no savings element → "Insurance"
   - Bank accounts → "Deposit" or "Savings"
   Do NOT use "Insurance" for plans classified as Savings, Protection, Health, or Investment.

5. TARGET_GOAL (max 50 chars)
   Concise description of the product's primary purpose.
   Examples: "Children's Education Planning", "Accident & Theft Protection",
   "Hospitalization", "Savings and Protection", "Female-focused Savings and Protection",
   "Savings, Protection and Wellness", "Children's Marriage Planning"
   Derive from product name first, then description. Always resolve to a concrete value.

6. CUSTOMER_TYPE
   EXACTLY one value: Salaried | Self-Employed | SME | Corporate | Retail | Government | N/A
   Products open to all bank customers → "Retail". NEVER use comma-separated lists.

7. EMPLOYMENT_TYPE
   If a "Target Market" section exists: extract the FULL list, semicolon-separated, verbatim.
   Example: "Salaried Individuals; Professionals (Chartered Accountants, Consultants,
   Doctors, etc.); Self-Employed Individuals, Proprietorships, Partners and Family
   Concern Business; Landlords, Housewives and Retired Individuals with consistent
   Rental Income/Foreign Remittances; Government/Semi-Government Employees and
   Employees of Armed Forces"
   If no Target Market section → "N/A". Do NOT default to "Salaried".

8. CUSTOMER_SEGMENT (max 50 chars)
   ONLY if the document explicitly labels a specific named demographic segment
   (e.g. "NRP", "HNW", "Overseas Pakistanis", "Roshan Digital Account holders").
   Do NOT derive from CUSTOMER_TYPE or paste the eligibility paragraph.
   If no explicit named segment → "N/A".

9. TARGET_SEGMENT (max 50 chars)
   ONLY if explicitly stated in the document as a positioning label.
   If not explicitly stated → "N/A".

10. SEGMENT_TIER
    ONLY if the document explicitly classifies the product as Premium / Mass Market /
    Retail / Niche. If not mentioned → "N/A".
    Do NOT derive from GENDER, MIN_CONTRIBUTION, or any other field.

11. MIN_AGE — Number only. From eligibility section. Example: 18
12. MAX_AGE — Entry age limit only (NOT maximum attained age). Number only.
    Example: "18 to 55 years" → MAX_AGE = 55.
    Do NOT use 85 if 85 is the maximum attained/coverage age, not the entry age.

13. GENDER
    "Female" — only if explicitly restricted to females.
    "Male" — only if explicitly restricted to males.
    "All" — only if document explicitly states the product is open to all genders.
    "N/A" — if gender is not mentioned in the document.
    Do NOT default to "All" just because an eligibility section exists.
    Presence of a Target Market section alone does not mean GENDER = "All".

14. IS_BANK_OFFERED — see Rule 5.

15. ACCOUNT_TYPE
    EXACTLY one of: Current | Savings | Wallet | Digital | N/A
    Insurance/takaful plans → "N/A". Use ONLY for actual bank account products.

16. CARD_TYPE
    Examples: Debit | Credit | Debit Card | Virtual Debit | Premium | Credit (Premium) | N/A
    Only if the product explicitly involves a card. Otherwise → "N/A".
    Extract the exact card type label from the document.

17. CHANNEL (max 30 chars)
    ONLY if explicitly stated. Examples: "Bank Alfalah branches", "Mobile App", "Online".
    If not stated → "N/A".

18. ELIGIBILITY_TYPE (max 100 chars)
    ONLY if brief eligibility criteria are explicitly stated.
    Example: "Bank Alfalah customers; one policy per unique CNIC"
    Example: "Bank Alfalah customers 18-59; renewable up to age 75"
    If not explicitly summarized → "N/A".

19. SERVICE_TYPE (max 30 chars)
    ONLY if explicitly stated in the document as a service type label.
    Do NOT derive from TARGET_GOAL. If not stated → "N/A".

20. REWARD_TYPE (max 30 chars)
    "Vitality Points" for Vitality wellness plans. "Points", "Cashback", "Profit" etc.
    If not stated → "N/A".

21. CURRENCY (max 30 chars)
    "PKR", "USD", "PKR + FCY". Default for Pakistan products → "PKR".

22. CURRENCY_TYPE
    "PKR" | "FCY" | "PKR + FCY" | "N/A"
    Use ONLY if document explicitly specifies currency type. Otherwise → "N/A".

23. MIN_BALANCE — Number only or "N/A"
24. AVG_BALANCE_REQUIREMENT — Number only or "N/A"
25. MIN_INCOME — Number only (PKR) or "N/A"
26. MIN_INCOME_USD — Number only (USD) or "N/A"
27. MIN_INVESTMENT — Number only or "N/A"

28. MIN_CONTRIBUTION
    Minimum annual contribution. Number only. Example: "PKR 25,000" → 25000.

29. LOAN_AMOUNT_RANGE (max 50 chars) — for loan products. Example: "200K-3M"

30. COVERAGE_AMOUNT (max 150 chars)
    Be specific about what is covered and amounts.
    Example: "Accidental Death up to PKR 1,750,000; ATM Withdrawal up to PKR 200,000"
    Example: "Hospitalization: Bronze PKR 150,000 / Silver PKR 300,000 / Gold PKR 500,000; Death PKR 100,000"
    Example: "Sehat Afza hospitalization cover: PKR 250,000 per annum"
    If not mentioned → "N/A"

31. FINANCING_TYPE (max 50 chars)
    EXACTLY one of: Conventional | Islamic | Takaful | Mudarabah | Unit Linked |
    Hybrid (Bonus Based and Unit Linked) | N/A
    - Plans with fund allocation tables, PIA, unit-linked investment → "Unit Linked"
    - Plans with BOTH bonus allocation (e.g. Yr6+ 3% bonus) AND unit-linked → "Hybrid (Bonus Based and Unit Linked)"
    - Takaful plans that are NOT unit-linked → "Takaful"
    - "Islamic", "Shariah-compliant", "Halal" → "Islamic"
    - "Mudarabah" explicitly mentioned → "Mudarabah"
    - No Islamic/Takaful language → "Conventional"
    ALWAYS check the product name and full text for "Takaful", "Unit Linked", "Shariah".

32. DEPOSIT_PROFIT_TYPE
    Variable | Tier-based | Fixed | Bonus-based | Bonus-based & Unit-linked | N/A
    - Unit-linked plans (PIA, fund allocation) → "N/A"
    - Health/protection plans (no savings component) → "N/A"
    - Plan with bonus allocation ONLY → "Bonus-based"
    - Plan with BOTH bonus + unit-linked → "Bonus-based & Unit-linked"
    - Use Variable/Tier-based/Fixed ONLY for traditional bank deposit/savings accounts.

33. DEPOSIT_PROFIT_FREQUENCY
    Monthly | Quarterly | Semi-annual | Annual | At Maturity | N/A
    - Unit-linked investment plans → "N/A"
    - Health/protection plans (no savings) → "N/A"
    - Traditional bank deposit accounts → extract stated frequency.
    CRITICAL: "Payment Frequency: Annual/Quarterly" = how CUSTOMER PAYS → goes to
    PREMIUM_PAYMENT_FREQUENCY, NOT this field.

34. TENURE (max 50 chars)
    Include full range and attained age if stated.
    Examples: "1 Year (renewable)", "10-25 years (up to attained age of 85)",
    "10-67 years (up to attained age of 85)", "10-57 years"
    Report both minimum term and maximum term/attained age when both are given.

35. TENURE_OPTIONS (max 50 chars)
    ONLY distinct plan DURATION choices (e.g. "10, 15, 20, 25 years").
    Do NOT use for contribution/premium payment frequency — that is PREMIUM_PAYMENT_FREQUENCY.
    If no distinct plan term duration menu → "N/A".

36. MIN_TERM_YEARS — Number only. Minimum plan term in years.
37. MAX_TERM_YEARS — Maximum PLAN TERM in years (not maximum attained age). Number only.
    Example: "Plan term up to 52 years" → MAX_TERM_YEARS = 52.
    If only an attained age ceiling is given (not a distinct plan term) → "N/A".

38. BUSINESS_TENURE (max 30 chars) — SME/business only. Example: ">=3 years". Otherwise "N/A".
39. COLLATERAL_TYPE (max 50 chars) — loan products only. Otherwise "N/A".
40. EQUITY_REQUIREMENT (max 20 chars) — loan products only. Otherwise "N/A".
41. DBR_LIMIT (max 20 chars) — loan products only. Otherwise "N/A".
42. TRANSACTION_LIMIT (max 50 chars) — if explicitly stated. Otherwise "N/A".

43. SPECIAL_CONDITIONS (max 200 chars STRICT)
    Include ONLY: one-policy-per-CNIC limits, waiting periods, ATM theft conditions,

    Do NOT include: free look period (use FREE_LOOK_PERIOD_DAYS), fee schedules,

44. PRODUCT_DESCRIPTION (max 250 chars)
    Concise summary of what the product is and its key differentiators.

45. PROVIDER_NAME (max 100 chars)
    The underwriter/provider name as stated in the document. Include "WTO" if

    Examples: "IGI Life Insurance WTO", "Jubilee Life Insurance WTO",
    "Bank Alfalah / Alfalah Insurance Company Limited-WTO",
    "State Life Insurance Corporation (SLIC)"
    Search the full document for "Underwritten by", underwriter name, or provider logo.

46. PRODUCT_VARIANT_TIER (max 50 chars)
    Tier/variant/package names as stated. Example: "Bronze, Silver, Gold, Platinum"
    If only one tier → that name. If no tiers → "N/A".

47. PRICING_RATE (max 400 chars)
    Full contribution amounts or pricing summary including all tiers/age bands.
    Examples:
    "Annual Contribution: Bronze PKR 5,000; Silver PKR 10,000; Gold PKR 15,000; Platinum PKR 20,000"
    "Yearly: PKR 36,000; Half-Yearly: PKR 18,000; Quarterly: PKR 9,000; Monthly: PKR 5,000"

    If truly not mentioned → "N/A".

48. FEES_AND_CHARGES (max 300 chars)

    Example: "Life cover + investment return; Death Benefit: Sum Covered + PIA + Surplus;

    Optional add-ons. Comma-separated (use commas not semicolons).
    Example: "Accidental Death Benefit, Income Benefit-Disability, Income Benefit-Death"
    Example: "Family Income Benefits, Critical Illness Takaful Benefit, Accidental Death

    Number only. Days of free-look/cooling-off period.

    Example: "Auto debit form; CNIC/NICOP/POC/Smart ID; Declaration form and T&C"
    Example: "Policy Schedule; Original Policy Documents; Death Certificate (NADRA/Union Council);

    Example: "http://igilife.com.pk/downloads/claim-forms/"
    Example: "Jubilee Life: (021) 111-111-554; info@jubileelife.com"
    Do NOT append lists of document names or claim form titles.

    Main exclusions from THIS product's own section. Semicolon-separated.
    Example: "War risks; Suicide within first year; AIDS and AIDS-related diseases;

    If not explicitly stated for this product → "N/A".
    Do NOT copy exclusions from another product in the same document.

55. TAX_ZAKAT_TREATMENT (max 100 chars)
    Only if explicitly stated for THIS product's section.
    Example: "Savings exempted from taxation; Zakat levied on maturity or surrender"

    Examples: "Annual, Semi-Annual, Quarterly", "Annual, Semi-Annual, Quarterly, Monthly"
    This is how the CUSTOMER PAYS — distinct from DEPOSIT_PROFIT_FREQUENCY.
    If not mentioned → "N/A".

STEP-BY-STEP EXTRACTION WORKFLOW
================================================================================

STEP 1: Identify product type
  → Insurance/takaful/protection/health? → LEAD_MARKER = "IBG"
  → Bank account/card/loan/deposit? → LEAD_MARKER = "BNK"
  → Set PLAN_TYPE: check if unit-linked (Savings), hospitalization (Health),
    accident-only protection (Protection), investment-primary (Investment),
    or other insurance (Insurance)

STEP 2: Product identity
  → PRODUCT_NAME from heading, Title Case
  → PROVIDER_NAME: search for "Underwritten by", underwriter, provider logo
  → SOURCE_FILE_PRODUCT = filename only

STEP 3: Set TARGET_GOAL
  → Check product NAME for purpose keywords
  → Read description/purpose section
  → Always resolve to a concrete value

STEP 4: Extract eligibility
  → MIN_AGE, MAX_AGE: entry age limits only, number only
  → GENDER: only if explicitly stated (Male/Female/All); "N/A" if silent on gender
  → EMPLOYMENT_TYPE: full Target Market list verbatim; "N/A" if no Target Market section

STEP 5: Financial structure
  → MIN_CONTRIBUTION = minimum contribution (number only)
  → FINANCING_TYPE: check for Unit Linked, Takaful, Islamic, Mudarabah, Hybrid
  → DEPOSIT_PROFIT_TYPE/FREQUENCY: "N/A" for unit-linked plans
  → PREMIUM_PAYMENT_FREQUENCY: from payment frequency table if present

STEP 6: Tenure and options
  → TENURE: full range including attained age ceiling
  → TENURE_OPTIONS: plan duration menu only, NOT payment frequency

STEP 7: Benefits, riders, exclusions
  → Each from THIS product's section ONLY
  → KEY_EXCLUSIONS, TAX_ZAKAT_TREATMENT: "N/A" if not stated for this product
  → FREE_LOOK_PERIOD_DAYS: only if explicitly stated for this product

STEP 8: VALIDATE before output
  ☑ All 56 fields present in each object
  ☑ No null/None/NaN/empty string — use "N/A"
  ☑ PRODUCT_NAME is Title Case
  ☑ PLAN_TYPE is one word from the allowed list
  ☑ GENDER is exactly one of: Male | Female | All | N/A
  ☑ CUSTOMER_TYPE has exactly ONE value (no commas)
  ☑ Numeric fields are plain whole numbers (no .0) or "N/A"
  ☑ SOURCE_FILE_PRODUCT has no folder path
  ☑ SPECIAL_CONDITIONS ≤ 200 characters
  ☑ FREE_LOOK_PERIOD_DAYS only if explicitly in THIS product's section
  ☑ DEPOSIT_PROFIT_TYPE/FREQUENCY = "N/A" for unit-linked plans
  ☑ ACCOUNT_TYPE = "N/A" for insurance/takaful plans
  ☑ TENURE_OPTIONS = plan duration choices only (not payment frequency)
  ☑ PREMIUM_PAYMENT_FREQUENCY = stated payment frequency or "N/A"
  ☑ FINANCING_TYPE includes "Unit Linked" for unit-linked plans
  ☑ No value copied from a different product
  ☑ Return one object per product (count sections first)

CRITICAL MISTAKES TO AVOID
================================================================================

MISTAKE 1: Wrong PLAN_TYPE
  WRONG: "Insurance" for a savings plan, health plan, or protection plan
  CORRECT: Use Savings | Health | Protection | Investment as appropriate

MISTAKE 2: DEPOSIT_PROFIT_TYPE/FREQUENCY for unit-linked plans
  Unit-linked plans use fund/PIA allocations, not deposit profit → both "N/A"

MISTAKE 3: GENDER defaulting to "All"
  WRONG: "All" merely because an eligibility/Target Market section exists
  CORRECT: "N/A" if gender is not mentioned; "All" ONLY if explicitly stated

MISTAKE 4: Deriving SEGMENT_TIER, SERVICE_TYPE, CUSTOMER_SEGMENT, TARGET_SEGMENT
  These are "N/A" unless explicitly stated in the document — do not derive them

MISTAKE 5: MAX_AGE = attained age
  "18 to 55 years of age (coverage up to age 85)" → MAX_AGE = 55

MISTAKE 6: TENURE_OPTIONS = payment frequency
  "Annual, Semi-Annual, Quarterly contributions" → PREMIUM_PAYMENT_FREQUENCY
  TENURE_OPTIONS = plan term duration options only (e.g. "10, 15, 20 years")

MISTAKE 7: FREE_LOOK_PERIOD_DAYS defaulting to 14
  Only set if THIS product's section explicitly mentions a free look period

MISTAKE 8: ACCOUNT_TYPE = "Savings" for insurance plans
  All insurance/takaful plans → ACCOUNT_TYPE = "N/A"

MISTAKE 9: Copying KEY_EXCLUSIONS / TAX_ZAKAT_TREATMENT cross-product
  Only extract if explicitly stated in THIS product's own section → else "N/A"

MISTAKE 10: ALL-CAPS PRODUCT_NAME
  WRONG: "JUBILEE KAMIL TAKAFUL SAVINGS PLAN"
  CORRECT: "Jubilee Kamil Takaful Savings Plan"

MISTAKE 11: FINANCING_TYPE missing "Unit Linked"
  Plans with PIA / fund allocation / unit-linked investment → "Unit Linked"

MISTAKE 12: CUSTOMER_SEGMENT = employment list
  WRONG: pasting the Target Market paragraph into CUSTOMER_SEGMENT
  CORRECT: "N/A" unless a specific named demographic segment (NRP, HNW) is labeled

MISTAKE 13: CLAIMS_SERVICE_CONTACT with appended document list
  WRONG: "http://url.com - Claimant Statement, Physician Statement, Death Cert"
  CORRECT: "http://url.com"

MISTAKE 14: CURRENCY_TYPE = "PKR" as default
  Only use "PKR" if document explicitly states PKR-only. Otherwise "N/A".

MISTAKE 15: EMPLOYMENT_TYPE = first item only
  WRONG: "Salaried" when Target Market lists 5 categories
  CORRECT: Full semicolon-separated list verbatim from Target Market section

MISTAKE 16: PROVIDER_NAME with "distributed via" boilerplate
  WRONG: "IGI Life Insurance (WTO), distributed via Bank Alfalah Ltd"
  CORRECT: "IGI Life Insurance WTO"

MISTAKE 17: Numeric fields with decimal point
  WRONG: "18.0", "250000.0"   CORRECT: "18", "250000"

MISTAKE 18: Skipping products near end of document
  Count all product sections first, then produce a complete JSON object for each one

MISTAKE 19: PRICING_RATE = "N/A" when a contribution/pricing table exists
  If MIN_CONTRIBUTION or any tier pricing table is present → fill PRICING_RATE

MISTAKE 20: OPTIONAL_RIDERS using semicolons
  WRONG: "Accidental Death; Income Benefit-Disability"
  CORRECT: "Accidental Death, Income Benefit-Disability" (use commas)
